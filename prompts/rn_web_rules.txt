# React Native Web implementation rules

Code
- Export the screen as `export default function $component() { ... }`.
- Import only from 'react', 'react-native', and the local icon component:
  `import Icon from '../generated-icon';`
- Use React state (useState) so controls are interactive: switches toggle,
  sliders move, tabs and segmented controls change selection, inputs accept text.
- No navigation libraries, native-only APIs, external packages, or network calls.

Canvas
- The screen renders in a fixed $canvas_width x $canvas_height point canvas with the
  same aspect ratio as the screenshot. All coordinates are in these points.
- The root View uses `flex: 1` and the screenshot's background color.
- Lay out content with flexbox. Use `position: 'absolute'` only for elements
  that overlay other content: floating buttons, floating or fixed bottom bars,
  badges, and elements pinned to the bottom of the screen.
- Content that is cut off at the bottom of the screenshot must also be cut off
  in the render; do not shrink content to make it fit.
- If the screenshot shows the phone status bar (time, signal, battery),
  reproduce it with a Text for the time and small Views for the indicators.

Typography
- fontSize is roughly 0.75 x the measured height of a single text line.
- Match font weight (400 regular, 500 medium, 600 semibold, 700 bold), color,
  alignment, and letter case exactly as shown. Copy all visible text verbatim.

Images and icons
- Never load remote or local image files (no `uri`, no `require`).
- Photos and banners: a View with the region's dominant color (or two stacked
  Views to approximate a gradient), the same size and corner radius, with any
  text that is printed on the image reproduced as Text on top.
- Small illustrations of objects (food, gifts, products): a single emoji with
  a fontSize matching the illustration size.
- Pictograms and UI icons: `<Icon name="..." size={..} color=".." />`.
  Available names: $icon_names.
  Add `filled` for solid icons. Pick the closest name; never draw icons as letters.
- Avatars: a circular View with the dominant color (and initials if shown).

Controls (build these from Views so they match the screenshot exactly)
- Button / icon button: TouchableOpacity with the exact background, border,
  radius, padding, and label or icon.
- Text input / search bar: View container with icon(s) + TextInput with
  `placeholder` and `placeholderTextColor` matching the screenshot.
- Switch / toggle: a rounded track View with a circular thumb View on the
  left (off) or right (on), using the screenshot's colors.
- Slider / seek bar / progress bar: a thin track View, a filled View whose width
  is the shown fraction, and (for sliders) a circular thumb at that position.
- Checkbox / radio: bordered square / circle View, filled with a check icon or
  inner dot when selected.
- Segmented control / chips / tags: a row of rounded Views; the selected item
  has the distinct background shown in the screenshot.
- Tab bar: a row of icon + label items. If it floats (rounded, inset from the
  edges, shadow), make it an absolutely positioned rounded View at the same
  position; otherwise a full-width bar at the bottom with a top border.
- Carousel: a horizontal ScrollView; if neighbouring cards peek in at the
  screen edges, reproduce the peeking cards at those positions.
- Badges / counters: small absolutely positioned rounded Views.
- Lists and grids: map over a data array; keep row heights, gaps, and column
  widths equal to the measured values.
